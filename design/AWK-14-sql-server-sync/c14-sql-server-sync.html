C14 · SQL Server sync example: nightly job and long-format tables · AWK-14 · 2026-10-15

An example to copy and adapt, in docs/integrations/sql-server-sync (Apache-2.0, outside the product). A small .NET console job pulls responses changed since its last run from the Public API with a key and upserts them into SQL Server in long format. Askwerk never connects to SQL Server.

1What the Public API needs first

Responses are not public yet. Two read endpoints (scope responses:read):

GET /api/v1/surveys/{id}/responses?since=0&limit=200
200 { "items": [ {
    "id": "…", "status": "complete", "version": 3,
    "language": "de", "participant": { "email": "…", "externalId": null },
    "startedAt": "…", "completedAt": "…", "changeSequence": 81234,
    "answers": [ { "variable": "SAT", "value": "4", "label": "Zufrieden" },
                 { "variable": "SOURCE", "value": "2", "label": "Werbung" },
                 { "variable": "SOURCE", "value": "OTHER", "label": "Messe" } ] } ],
  "nextSince": 81240 }
GET /api/v1/surveys/{id}/codebook?language=de
200 { "variables": [ { "variable": "SAT", "question": "Wie zufrieden…",
       "type": "rating", "values": [ { "code": "1", "label": "…" } ] } ] }

changeSequence is a number that grows with every change to a response (new answers, completion), across the organisation, so “since” never misses one. Matrix rows become variable_row (SAT_SERVICE); multiple choice gives one row per chosen code.

Long format: one row per response, variable and chosen value. Reports join askwerk_answer to askwerk_value_label; nothing changes shape when a survey gets a new question.

3The job

appsettings.json
{ "Askwerk": { "BaseUrl": "https://surveys.acme.at",
               "ApiKey": "awk_…", "Language": "de",
               "Surveys": [] },          // empty = all published
  "SqlServer": { "ConnectionString": "…" } }
  1. For each survey: read last_sequence from askwerk_sync_state.
  2. Refresh the codebook (upsert variables and labels).
  3. Page through responses since last_sequence; per page, in one transaction: MERGE responses, delete and insert their answers, store nextSince.
  4. Log a line per survey; exit code 0, or 1 with the error stored in last_error.
  • Restart-safe and idempotent: a crash repeats at most one page; rerunning changes nothing.
  • Runs from Task Scheduler, cron or a container (Dockerfile included); nightly or every 15 minutes.
  • Tested against SQL Server 2022 in a container (Developer edition, only in the example's tests) and a real Askwerk.

DE/EN: the job logs in English; labels come in the language chosen in appsettings.json. Email and PDF: not involved.
