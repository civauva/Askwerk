  • Any 2xx within 10 s counts; otherwise retries after 1 min, 5 min, 30 min, 2 h, 6 h, 12 h, then failed.
  • At-least-once: receivers deduplicate by id. Sent through the job table (outbox), so a rolled-back change sends nothing.
  • A webhook failing for 3 days is paused; the API page says so and Resume starts it again.

B · OAuth 2.0 client credentials

POST/api/v1/oauth/token application/x-www-form-urlencoded
grant_type=client_credentials
client_id=cl_4b8…&client_secret=…     (or HTTP Basic)
scope=surveys:read responses:read       (optional subset)

200 { "access_token": "awt_…", "token_type": "Bearer",
      "expires_in": 900, "scope": "surveys:read responses:read" }

Errors as RFC 6749 requires: 401 invalid_client, 400 invalid_scope, 400 unsupported_grant_type. Rate-limited per client.

  • The token is sent like a key: Authorization: Bearer awt_…; every /api/v1 endpoint accepts both.
  • Tokens live 15 minutes; deleting the client ends them at once.
  • Clients are created where keys are: Organisation → API, “OAuth clients”, with the same presets (Read results, Full access) and expiry. The secret is shown once.

C · MCP server

POST/mcp Streamable HTTP, JSON-RPC 2.0

Authenticated with an API key or an OAuth access token; it can never do more than the Public API with the same scopes.

Tools now

  • list_surveys {status?, search?} → surveys
  • get_survey {surveyId} → survey with its definition
  • start_export {surveyId, format, filter?} → export
  • get_export {exportId} → status and download link

New tools appear as their endpoints become public (create survey, publish, list responses).
