Two lines, one tag

  token="eyJ…"            <!-- signed by the portal's server -->
  look="host"             <!-- follow the portal's colours -->
  lang="de">

// the portal decides where Results and Edit go
list.addEventListener("askwerk:open", (e) =>
  router.go(`/feedback/${e.detail.surveyId}/${e.detail.view}`));
How it works

A tag that loads a frame

  • Each component is a thin loader around the same signed frame Askwerk already embeds: one code base, nothing to keep in step.
  • The portal's server signs who is working (the hand-over token, as today); roles come from the token.
  • The frame grows with its content, so it reads as part of the page.
  • Works in React, Angular, Vue or plain HTML; no framework, no build step.

The host look

Four values, not a theme editor

  • accent · background · font · corner radius.
  • Given as CSS variables on the tag (--askwerk-accent …) or set once in Askwerk (D); Askwerk's own logo and colours step back.
  • The survey respondents see keeps the survey's own look unless it is set to follow the host.

Notes

The key result goes anywhere

  • <askwerk-result> is the key result of the survey cards (W38), on its own: one question, one number, live.
  • Who may see what comes from the token's role (viewer, analyst), as in Askwerk.
  • The data stays in Askwerk; the portal never stores answers unless it fetches them with the API.

Effort and upkeep

Small, because it reuses the frame

  • components.js: ~4 custom elements over the existing embed frames and events; no second UI.
  • New: the host look (4 values), <askwerk-surveys> and <askwerk-result> screens for embedding, chrome="none".
  • Not proposed: in-page React components sharing the host's DOM — every Askwerk change would break hosts.
  • Estimate: 1.5–2 days, with tests and docs.
