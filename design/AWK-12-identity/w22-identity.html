Switched off (the default): the page shows only the first line and “Connect your own sign-in” as a hint. An owner always keeps an Askwerk account, so nobody is locked out when a provider fails.

2Hand-over (main path)

Set uppaste the host's public key (PEM or JWKS URL), issuer and audience; Askwerk shows its own audience value to copy. Keys can be rotated: two may be active. Sign inhost signs a JWT (RS256/ES256): iss, aud, sub (host user id), email, name, roles or groups, exp ≤ 5 min, jti → POST /handover or /handover?token=… Askwerkchecks signature, issuer, audience, expiry and that the jti is new; creates or updates the user and membership; maps roles; starts the session (or an embedded one, AWK-13); audits user.handover. Errorsbad signature / expired / used token → “This sign-in link no longer works. Start again from your product.” (DE: „Dieser Anmeldelink gilt nicht mehr. Starten Sie erneut in Ihrem Produkt.“)

3OIDC and LDAP

OIDCissuer URL (discovery), client id and secret, scopes; the sign-in page shows “Sign in with Acme” above the password form. Authorization-code flow with PKCE; email and groups from the ID token or userinfo. LDAPserver, port, LDAPS, bind user, base DN, user filter, group attribute. The sign-in form checks the password against the directory; nothing is stored. “Test connection” with a test user. Botha user is matched by the provider's id, then by email once; first sign-in creates the membership with the mapped role; if no rule matches and “not let in” is set: “Your account has no access to Acme GmbH. Ask your administrator.”

4Provisioning API (Public API, scope users:manage)

PUT    /api/v1/users/{externalId}      { email, name, role, active }
GET    /api/v1/users?cursor=
DELETE /api/v1/users/{externalId}      → deactivated, never deleted
  • The host stays the master: changes in Askwerk's Members page are locked for provisioned users (“Managed by HR Suite”), as W18 promised.
  • External ids live in ExternalReference (data model W2); responses keep their person after deactivation.
  • Audit: user.provisioned, user.deactivated, membership.role-changed with the key or client as actor.

Respondents identified by the host use the same hand-over token (survey audience); see W21 for embedding.

New dependencies needed, to be confirmed one by one before they are added: Microsoft.AspNetCore.Authentication.OpenIdConnect (MIT, Microsoft) for OIDC; System.DirectoryServices.Protocols (MIT, Microsoft) for LDAP. JWT checks for the hand-over can be done with .NET's own crypto (no package).
